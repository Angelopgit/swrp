# SWRP - project guide for Claude

Star Wars: Clone Wars roleplay multiplayer gamemode for s&box (engine 26.10.02, C# + Razor). A framework in the spirit of Garry's Mod
DarkRP / NutScript / Helix, with its own take: whitelisted legions, saved characters, ranks, inventory, roleplay chat with voice
ranges, staff tools. Setting: clone troopers aboard a Venator-class Star Destroyer. Players: up to 64, host-authoritative.

`README.md` is the player and admin command list. Do not duplicate it here; update it when commands change.

## Where to edit for each thing

- New faction or rank: `Data/Factions.cs` only. Ranks are the single ladder there.
- New class: `Data/Classes.cs` (model path must exist, otherwise the Citizen fallback logs a warning).
- New item or weapon: `Data/Items.cs`.
- New chat command: the `switch` in `Server/SwrpChat.cs` and the `/help` text. Staff command: `Commands` in `Server/SwrpStaff.cs`.
- Door names and access levels: `RULES` in `MapSource/notorious_doors.py`, then rebuild.
- New admin console command: `SwrpCommands` in `Server/SwrpGameManager.cs`.
- New UI sound: add it to `SoundSource/ui_sounds.py`, rerun, then use `sound-in: "sounds/ui/<name>.sound"` in the scss. Feel sounds (footsteps, impacts, whooshes): `SoundSource/feel_sounds.py`.
- Colours, type, spacing, motion and target brightness: `STYLE_GUIDE.md` (and `Code/Feel/_feel.scss` for panel styles).

## Conventions

- Host is authoritative. Clients call `[Rpc.Host]` methods (see `SwrpChat.SendToHost`, `SwrpNet`); the host validates role/whitelist and then mutates `[Sync]` state.
- Persistent data is host-side JSON under the s&box data folder `swrp/`: `characters/<steamid>.json`, `whitelist.json`, `punishments.json`. Go through `CharacterStore`, `Whitelist` and `SwrpStaff`; never edit save files by hand while the server runs and never from tests.
- Tabs for indentation, spaces inside parentheses (`Foo( x )`), the same style as the surrounding file. Namespace `Swrp`.
- Components get fetched with `GetComponent`, not `[Property]` references to the player controller (these caused null-reference floods).
- Do not name a property `Enabled` on a component (hides `Component.Enabled`).
- Original audio only: sounds are synthesized by `SoundSource/ui_sounds.py`.

## Build, run, verify

- The s&box editor must be open on this project. It exposes an MCP endpoint at `http://127.0.0.1:7269/mcp` (tools via `call_tool`: `compile_status`, `read_console`, `play_start`/`play_stop`, `camera_screenshot`, `asset_compile`, `set_component`, `switch_scene`), even when the configured `sbox` MCP server reports a failed connection.
- After code edits: check `compile_status` and the console for errors. Then play and watch the `[PERF]` lines (target 90-120 fps; current build holds 120).
- Map rebuild (Blender 5.2, `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`, run with `-b --factory-startup -P`):
  `MapSource/gmod_textures.py` (VTF/VMT to PNG and vmats, writes `gmod_materials.json`), then `python MapSource/gmod_style.py` (glossy floors, emissive lights), then `MapSource/notorious_build.py` (brushes to FBX, ceiling light strips, `notorious_entities.json`, via `notorious_doors.py` the door data and `MapSource/doors_review.md`, via `notorious_props.py` + `source_mdl.py` the props as chunk models listed in `Assets/data/notorious_props.json`; never-solid func_brush shields render faint and get no collision; props collide with their `.phy` convex pieces, stored in each chunk's own vmdl; all-tool-texture button/mover brushes and NPC clip get no collision; `special_material()` turns sky_fake_white into the light-panel glow and GLASS_CLEAR into visible glass; `bridge_dressing()` adds bridge furniture), then `python MapSource/notorious_scene.py` (rebuilds the scene: spawns, lights, jail cells, camera effects, turbolifts and teleport pads from `notorious_transit.py`'s JSON). `MapSource/regions.py` holds the skybox box (the only part left out) and the playable areas (ship, Jedi temple, simulation rooms). Wait about 10 s, run `asset_compile` on `models/notorious/notorious.vmdl` and each vmdl in `notorious_props.json`, `switch_scene`. Don't pipe the Blender run into `head` (it cuts the export short).
- Use system Python for the plain scripts and Blender's Python for anything importing `bpy` (system Python has no numpy).

## Gotchas we have hit

- Clients only get compiled assets: a loose `Assets/data/*.json`/`.bin` read with `FileSystem.Mounted` exists on the host only (found 2026-10-21 with the first second client: doors without geometry, empty holo-map, no Tatooine ground). Read data through `SwrpDataFile.ReadText/ReadBytes/Exists` and rerun `python MapSource/wrap_data.py` (writes `<file>.swdat`) after regenerating map, terrain, droideka or GMod aim data; new data files go in its FILES list. Test client paths with sbox-cli `network_spawn_instance` (a fake identity, not Cub); its log is `logs/sbox.log`. New small assets reach local instances only after play restarts.

- Editor recompile loop (about 3 fps): FBX imports are cached by file name and unregistered model files make the editor recompile forever. `notorious_build.py` writes a new revision name plus a `.meta` and keeps the previous revision. Keep that behaviour; after compiling, re-assign `Model` on the map object to reload.
- `notorious.scene` is generated; edits made in the editor to lights or the map object are lost on the next `notorious_scene.py` run. Make scene changes in the script.
- Tests or tools that rewrite `ProjectSettings` or strip scene UI panels have broken the project before; check `git diff`-style changes (UI object, `Platform.config`, `Input.config`) after test runs.
- Remote Control and a second editor on the same files fight each other: use one editor at a time.
- Asset compiles can stick: a material whose mask and colour point at the same PNG recompiled forever (gmod_style now uses a flat mask), and chunk vmdls can fail with "waited too long for quiet inputs" while a game is running; stop play or restart the editor, then `asset_compile` again.
- Clone animations (`X:\SWRP Projects\Clonetrooper\sbox_build\anim`, see its REPORT.md): author on the s&box human *reference* skeleton (the clone vmdl adds clone-minus-reference to every clip), apply the importer's object transform so exported clips get the clone FBX's root (null -90 X, x100 over pelvis), the hold_R/hold_L attachment is the bone's FBX frame (barrel = Blender bone Y), and two-handed poses must set `hand_L_to_R_ikrule`/`hand_R_to_L_ikrule` to the other hand or the graph drags the off hand away. `install_clone_anims.py` rewrites `clone_animationlist.vmdl_prefab` and the `_drill` vmdls; extra named AnimFiles in them fail with "Node resolve failure". Some stock Human@ clips are ASCII FBX that Blender can't read.
- Audio is synthesized only (`SoundSource/*.py`, run with Blender for numpy). The menu theme loops seamlessly (tail folded onto the start); `Code/UI/MenuMusic.cs` plays it from the character screen, or a user-supplied `sounds/music/menu_custom.*` they own. Never download or rip music.
- Hot-reload keeps static fields: after changing static data (ClassRegistry, ItemRegistry, FactionRegistry, the staff `Commands` table, `Input.config`) the running editor still uses the old values. Restart the editor before testing those.
- A new `GameObjectSystem` class added during a hot-reload is not created in the running scene until the scene loads again (seen 2026-10-15 with the held build tools): tick new work from an existing system, or reload the scene before testing it.
- Launching or focusing the editor window steals keyboard focus, so whatever the user types goes into the game. Don't bring it to the front while they may be typing.
- Bash heredocs containing quotes failed repeatedly; write patch scripts to a file and run them.
- `MapSource/notorious_build.py` runs `main()` when imported: importing it from a helper script rebuilds the whole map. Import `vmf_parse`, `regions` or `notorious_props` instead, or probe in play with `swrp_probe` / `swrp_look`.
- Engine quirks met in the cinematic pass: `ColorGrading` curves have no effect (only `TemperatureControl` + `ColorTempK` works; lower K = warmer); runtime quads built from `Mesh` did not render, use `SpriteRenderer` with `Sprite.FromTexture`; a `WorldPanel` draws about 0.05 units a pixel and needs `RenderOptions.Game = true`; UI `background-image` PNG alpha came out far too weak, so overlays use CSS gradients; a hidden renderer drops `Materials.SetOverride`, so the navy crewman is its own vmdl with remapped materials.
- Walking up `GameObject.Parent` ends at the `Scene`, which is itself a GameObject, and a component search from it covers the whole map. Stop the loop at `Sandbox.Scene` (in razor, `Scene` alone means the component's scene property) and search with `FindMode.EverythingInSelf`; that slip once made every door's E prompt the armory rack.
- The sky texture's Y runs the other way round from world Y (see `grid()` in `space_sky.py`); `swrp_cam` pitch is positive down; facing the bow (-Y), +X is on the left.
